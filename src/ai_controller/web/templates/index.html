Elastic clusters

Default MCP skill vector

CVSS-style string copied onto every new cluster. Each cluster can then override it. Sessions use the vector of the cluster they are bound to. Example: MSV:1/IRIS:N/SIEM:Y/EDR:N/SK:create_case=N

Configured clusters

Each session and autorun binds to one Elastic cluster. MCP SIEM tools use that cluster’s URL and credentials.

Add cluster

Use the Elasticsearch API URL when possible (usually port 9200). Kibana (5601) can be saved and tested, but search tools expect Elasticsearch. SIEM query skills include KQL, Lucene, EQL, Query DSL, and ES|QL (search_kql_query, search_lucene_query, search_eql_query, search_dsl_query, search_esql_query) — toggle them under Edit skills.

Activity log

Every button on this page writes here and to the browser console as [Elastic]. Server logs are in logs/debug.log under sami.web.elastic.

NetBox

DCIM/IPAM enrichment for hosts, IPs, and prefixes during investigations.

Connection

Map NETBOX_URL → Base URL and NETBOX_TOKEN → API token. Skills: netbox_lookup_ip, netbox_lookup_host, netbox_lookup_prefix, netbox_search. Enable them on Elastic clusters with the NB skill-vector metric.
